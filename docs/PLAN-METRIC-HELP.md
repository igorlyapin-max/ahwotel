# План: подробные подсказки по параметрам AHWOTel

Дата: 2026-09-13. Основание: прямой запрос пользователя. Статус: реализован в APK 0.2.1, сценарные проверки выполнены; см. [отчёт](VALIDATION-0.2.1.md). Правило для последующих изменений сохранено в корневом `AGENTS.md`.

## Результат

Пользователь открывает справку у параметра и понимает, что измеряется, как это связано с работой устройства или приложений и как читать значение и график. Все пояснения доступны офлайн на выбранном языке AHWOTel: English или Русский; первоначальный язык — English независимо от языка Android.

## 1. Охват и содержание

Создать справочник для всех 22 значений `Metric`, включая показатели, которые сейчас видны только в Diagnostics или экспорте:

| Группа | Показатели |
| --- | --- |
| CPU | CPU, CPU_WAIT, PROBE_DELAY, CPU_PRESSURE |
| Память | MEMORY_TOTAL, MEMORY_AVAILABLE, MEMORY_PERCENT, MEMORY_LOW, MEMORY_THRESHOLD, MEMORY_PRESSURE |
| Хранилище | STORAGE_TOTAL, STORAGE_AVAILABLE, STORAGE_USED, STORAGE_PERCENT, STORAGE_PRESSURE |
| Нагрев | THERMAL, HEADROOM, THERMAL_PRESSURE |
| Батарея | BATTERY, CHARGING, TEMPERATURE |
| Общая оценка | STATE |

Каждая подсказка содержит:

1. Что это за параметр: простое определение, область измерения (устройство, поток пробы, раздел данных приложения или вычисляемая оценка).
2. Единицы, шкала и способ получения значения; для интервальных показателей — смысл измерительного окна.
3. На что указывает изменение и с какими последствиями для отзывчивости, выполнения задач, памяти, хранения, нагрева или автономности оно связано.
4. Как интерпретировать высокие/низкие значения, длительный тренд и краткий всплеск; числовые коды категорий и флагов расшифровываются.
5. Короткий числовой пример с единицами и оговорками, если они нужны для корректного прочтения.
6. Ограничения и возможные сопутствующие причины; как проверить предположение с помощью других показателей.
7. Участие в Performance State либо явное указание, что показатель в оценке не участвует.
8. Источник и технический идентификатор в дополнительном разделе «Источник измерения» / «Measurement source».

Перед написанием EN/RU текстов сверить смысл с `Collectors.kt`, `CpuProbe.kt`, `Core.kt`, `Database.kt` и первичными источниками Android/Linux для соответствующих API. В частности: ожидание CPU относится к потоку пробы и измерительному интервалу; задержка пробы не равна времени запуска приложения; температура батареи не является температурой CPU; хранилище относится к разделу данных приложения. Косвенные CPU-показатели не входят в существующий Performance State.

Для pressure/state описать шкалу, пороги, окна повышения/восстановления и частичную оценку при недоступных источниках. В этой итерации справка объясняет правила; числовые примеры порогов явно помечаются как значения по умолчанию. Текущие настройки не выдаются за пороги старой сессии, а косвенным CPU-сигналам не назначаются новые пороги «нормы».

## 2. Общий компонент справки

- Добавить `MetricHelp.kt`: исчерпывающее сопоставление `Metric` с ресурсами разделов справки. Метаданные содержат resource IDs, а строки разрешаются по текущей locale при отображении.
- Добавить `MetricHelpSheet.kt`: общую прокручиваемую панель Material 3, открываемую кнопкой «ⓘ» с локализованным описанием «О параметре …» / «About …».
- Предусмотреть закрытие кнопкой и системной Back, прокрутку длинного текста, область нажатия не менее 48 dp, TalkBack и увеличенный шрифт. Закрытие возвращает к исходной карточке и позиции прокрутки.
- Хранить идентификатор выбранного показателя через `rememberSaveable`; не кешировать готовый текст без учёта языка. Открытие справки не запускает измерение или ручную проверку источников.

## 3. Точки входа

- **Monitor:** кнопка у каждой карточки метрики и у Performance State.
- **History:** кнопка рядом с названием каждого графика; доступна также при No data. Справка графика объясняет min/avg/max, агрегацию и разрывы данных; для pressure/state учитывает фактическое отображение максимального уровня в интервале.
- **Settings:** кнопки у групп сборщиков и Indirect CPU signals открывают список соответствующих параметров с переходом к подробным подсказкам. Доступность не зависит от переключателя сбора.
- **Diagnostics:** кнопки у результатов проверки и отдельный вход «Справочник параметров» / «Metric guide», содержащий все 22 параметра даже до первого запуска мониторинга.
- Использовать единый текст для одного параметра на всех экранах. Существующие короткие пояснения CPU-проб оставить как краткое описание рядом со значением.

## 4. Язык, доступность данных и контекст

- Полные парные ресурсы в `values/strings.xml` и `values-ru/strings.xml`: разделы, примеры, элементы управления, объяснения статусов, источников, причин и accessibility labels.
- После Settings → Interface language → Save settings все подсказки открываются на сохранённом языке; выбор сохраняется после перезапуска приложения.
- Пояснить AVAILABLE, DISABLED, WARMING_UP, UNSUPPORTED и ERROR, а также отсутствие истории. Недоступное значение не означает ноль или отсутствие проблемы.
- Добавить локализованные объяснения существующих `SourceReason`, включая запрет доступа, отсутствие API, прогрев, паузу, сон и устаревший замер. Сохранять технические коды для сопоставления с логами.
- В Diagnostics показывать пояснение фактического результата последней проверки с её временем. Справка в History не переносит текущий статус источника на исторический график; если исторический контекст не используется, показывать общие пояснения явно как справку.
- Поддержка legacy-форматов подсказок не планируется: новая справка поставляется ресурсами APK, её собственное хранилище и миграция не требуются.

## 5. Проверки и критерии приёмки

Validation scope: новый справочник, локализация и затронутые Android UI-пути. При подготовке плана runtime-тесты не требовались; результаты сценариев реализации приведены в отчёте проверки.

| Сценарий | Ожидаемый результат и доказательство |
| --- | --- |
| Полнота справочника | Для каждого из 22 `Metric` есть все обязательные непустые разделы EN/RU; добавление метрики без справки приводит к ошибке проверки. |
| Первый запуск | В чистом тестовом профиле приложение и справка открываются на английском, в том числе при русском языке Android. |
| Переключение EN → RU → EN | После сохранения и после перезапуска заголовки, основной текст, примеры и accessibility labels соответствуют выбранному языку. |
| Все точки входа | Monitor, History, Settings и Diagnostics открывают справку нужного параметра; справочник доступен до первой сессии. |
| Отключено / недоступно / нет данных | Можно открыть справку; видны понятные объяснения, отсутствующие значения не представлены нулями. Показ истории не получает текущий статус источника. |
| Маленький экран и крупный шрифт | Длинные подсказки CPU wait, HEADROOM и STATE полностью доступны прокруткой, кнопки видимы и нажимаются; возврат сохраняет контекст. Снимки EN/RU подтверждают фактическую видимость. |
| Открытие во время сбора | Справка не останавливает сессию, не инициирует дополнительные чтения источников и не изменяет настройки; вне сессии её открытие не создаёт замеры. |
| Обновление APK | Новый APK устанавливается поверх 0.2.0 с сохранением истории, выбранного языка и настроек. |

Проверки: `python3 scripts/check-locales.py` с дополнением проверки полноты справочника; focused unit/resource tests; Compose instrumented tests для справки; `:app:lintDebug`, `:app:assembleDebug`, `:app:assembleDebugAndroidTest`. Для инструментальных тестов использовать существующий runner с фильтром новой тестовой группы; полный набор не расширять без причины.

Verification prerequisites: локальные JDK/SDK через `scripts/gradle.sh`, доступные ADB-устройства с явным serial, разрешение USB debugging и разблокированный экран. На время UI-сценария использовать тестовый keep-screen-on; системные настройки рабочего телефона не менять. Проверить на SM-J260F, если он подключён, и эмуляторе API 35. Чистый профиль и крупный шрифт проверять на эмуляторе, сохраняя пользовательские данные телефона.

Evidence: отчёт тестов, снимки видимых подсказок EN/RU, подтверждение возврата в исходный экран, сохранённого языка после перезапуска и истории после обновления. Наличие ресурса или UI-элемента без фактической читаемости не закрывает сценарий.

## 6. Поставка при реализации

Подготовить APK 0.2.1 (versionCode 3) с прежним debug signing key, обновить README и acceptance-сценарии. Приложить APK, SHA-256 и отчёт проверок; выполнить перезапуск и проверку нового интерфейса на тестовом устройстве. Существующие Off/Basic/временный Verbose и structured logging stdout/stderr + Logcat сохраняются; подсказки не требуют отдельного logging pipeline.

Объём — тексты справки и UI-доступ к ним. Алгоритмы сбора, CPU fallback, пороги оценки, схема Room и wire-форматы экспорта остаются за пределами этого изменения. Commit/push выполняются только по отдельному запросу.

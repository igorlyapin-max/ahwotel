# AHWOTel: руководство заказчика по Samsung Knox

Актуальность: 2026-11-18. Эта интеграция работает внутри AHWOTel. SDK в сторонние бизнес-приложения не устанавливается. Поддерживается Android 8+, compile/target API 36; базовый Knox SDK сборки — 3.13/API 40. Это не минимальная версия Knox на устройстве: каждый вызов проверяется отдельно.

## Что добавляет расширение

В Settings → Samsung Knox доступны импорт ключа, активация, проверка платформы и диагностика. OEM → категория Устройство содержит четыре показателя Samsung DeviceInventory: общий/доступный объём внутренней памяти и внешней SD-карты. Это ёмкость в байтах, не скорость I/O. По умолчанию эта категория собирается раз в сутки и при старте сессии; для эксперимента можно изменить интервал через существующий Custom profile. Android и Knox хранятся отдельными источниками.

Все четыре метода deprecated с Knox API 35. На конкретной прошивке возможны отсутствие метода, ответ -1 или отказ доступа. Такие результаты сохраняются как отсутствие данных/ошибка доступа с null, не как нулевые физические значения. Системный CPU, OEM-температуры и износ батареи не появляются автоматически: подходящие официальные API не подтверждены. Стандартные Android-измерения продолжаются независимо. [Матрица методов и SDK](knox-api-matrix.md).

## Регистрация и ключи

1. Зарегистрируйте корпоративный Samsung account и Knox Developer/Partner account; пройдите одобрение требуемого уровня доступа.
2. В Knox Developer Portal: SDK Tools → SDK Downloads → Knox SDK. Примите условия SDK и скачайте пакет 3.13/API 40 для воспроизводимой сборки. Для эксплуатации заказчику нужен готовый APK, не Android Studio и не JAR.
3. License keys → My license keys → ACTIONS → Get a license key. Для пилота выберите DEVELOPMENT KEY; для промышленной эксплуатации получите подходящий COMMERCIAL KEY с нужными entitlements.
4. Выполните app association: загрузите именно распространяемый APK через EXTRACT PACKAGE. Основной package — `com.ahwotel`; тестовый — `com.ahwotel.acceptance`, ему нужна отдельная допустимая association. Проверьте данные пакета и подписанта, которые извлёк портал.
5. При смене package/подписанта, переходе с debug на production signing или замене ключа повторно проверьте association до распространения. Не меняйте подпись действующего APK без плана сохранения данных: обычное Android-обновление требует совместимой подписи.

| Материал | Кто получает и где используется |
|---|---|
| KPE development key AHWOTel | Разработчик/ответственный администратор: локальный пилот AHWOTel. Ограничения срока/числа устройств берутся из портала. |
| KPE commercial key AHWOTel | Заказчик/уполномоченный партнёр: эксплуатация именно APK AHWOTel после association. |
| Лицензии SOTI/KPE его агента | Администратор MDM: настройка управляющей платформы. Они не доказывают права или активацию AHWOTel. |
| Backwards Compatible Key | Только при условиях Samsung: старые Knox 2.7 и ранее либо отдельные legacy-лицензии. Текущий адаптер рассчитан на Knox 3.x и не активирует BCK; такие устройства/лицензии требуют отдельной интеграции. |
| mTLS certificate/private key | Отдельная PKI для OTLP; не заменяет KPE. См. [mTLS](mtls-ru.md). |

Наличие developer account не выдаёт права на каждый API. Стоимость, право на commercial key, квоты и сроки определяются текущими условиями Samsung/договора: категории KPE и предложения порталов различаются, универсальное обещание бесплатности здесь не даётся.

## Локальный пилот

1. Установите AHWOTel на физический Samsung с поддержкой Knox, штатной прошивкой, интернетом и правильными часами. Эмулятор не подтверждает реальные Knox-возможности.
2. Подготовьте UTF-8 файл с одним ключом, до 4096 байт. В локальной разработке SDK лежат в `.tools/knox/`, dev key — `secrets/ahwotel-dev-knox.key`; эти каталоги исключены из Git. Ключ не встраивается в APK.
3. Settings → Samsung Knox → Импортировать файл лицензии. Выберите файл через системный picker; после импорта отображается только наличие ключа.
4. Нажмите Активировать лицензию Knox. Если Samsung запрашивает согласие/EULA, подтвердите его вручную после ознакомления. AHWOTel не принимает его автоматически и не делает себя Device Owner.
5. Дождитесь результата. На Knox API 35+ используется callback; показаны код и число разрешений из последнего подтверждённого callback. На старых версиях broadcast используется только как сигнал повторного чтения официальной записи; его extras не считаются доказательством успеха. Ни наличие записи, ни успешный callback не подтверждают доступ ко всем getters.
6. Включите OEM/Knox и категорию Устройство, начните сбор и проверьте фактические значения и причины недоступности. Подсказки доступны через (i), недоступные показатели находятся в нижнем сворачиваемом блоке. Затем проверьте History/ZIP и, при необходимости, OTLP.

Ключ сохраняется зашифрованным AES-GCM с ключом Android Keystore в приватных preferences. allowBackup=false. Он не входит в Settings/portable schema 4, экспорт истории, OTLP или логи. Переданный через SAF файл остаётся в исходном месте: приложение его не удаляет. Управление доступом к файлу и MDM-консоли остаётся у администратора.

## Массовое распространение через SOTI

На стороне SOTI оставьте существующий агент Device Owner. Доставьте подписанный APK в нужный профиль/пользователя и portable deployment profile обычным способом. Ключ KPE передаётся отдельно через Android managed application restrictions, в контролируемой конфигурации SOTI:

```json
{"knox_license_key":"REPLACE_WITH_CUSTOMER_KPE_KEY","knox_license_action":"activate"}
```

JSON выше — пример отдельных restrictions, а не содержимое portable profile. Не помещайте туда development key из репозитория; используйте ключ заказчика, связанный с установленным APK. SOTI хранит значение в своей конфигурации, а Android предоставляет application restrictions приложению: ограничьте доступ администраторов к этим поверхностям. Переносимый экспорт AHWOTel этот ключ не содержит.

Если команда `activate` пришла первой, AHWOTel показывает «Ожидается лицензионный ключ» и обработает ключ при последующей доставке действующей команды. После подтверждённого результата повторная доставка того же ключа и команды не вызывает активацию. После прерывания AHWOTel сверяет состояние у Samsung и может один раз повторить незавершённую попытку с задержкой. Для явного повтора уберите `knox_license_action`, дождитесь применения и снова доставьте `activate`. Новый ключ начинает новую попытку. Снятие action оставляет лицензию и сохранённый управляемый ключ. Ручной импорт поверх управляемого ключа заблокирован. Полный профиль управляет остальными настройками приложения. Сбой обработки лицензии виден отдельно и не отменяет применение профиля мониторинга.

Проверьте статус и фактические getters на пилотной группе, затем расширяйте назначение. Версия SOTI заказчика 2026.2.2.1001: доступность конкретного редактора application restrictions, app association и результат на устройстве требуют проверки в его среде. Наличие прав у SOTI/KSP не передаёт их AHWOTel автоматически. Если getter требует отдельной административной роли, AHWOTel покажет отказ; широкие права и изменение политик без документированного основания не запрашиваются.

## Продление и ошибки

Перед истечением ключа получите продление/замену у Samsung, проверьте association и доставьте новый ключ с action. Автоматическая деактивация не реализована; отзыв и удаление активаций выполняются по процедуре Samsung администратором. При переустановке с удалением данных/import key потребуется заново; при install -r с прежней подписью приватные данные сохраняются. Удаление приложения/устройства из SOTI не является доказательством отзыва лицензии у Samsung.

| Симптом | Проверка |
|---|---|
| Knox недоступен | Samsung/штатная ОС, системная Knox-библиотека, версия и поддержка модели. |
| Ключ задан, успеха нет | Кнопка активации или действие MDM, доступ к KLMS, часы, association APK. |
| Неверный ключ/подписант/истёк срок/квота/отказ пользователя | Код из SDK сверить с официальным KnoxEnterpriseLicenseManager; проверить entitlement, сроки и согласие. Не пересылать сам ключ в логах. |
| Ожидание более двух минут | Статус timeout; проверить сеть, Samsung consent и выполнить явный retry. |
| Запись активации есть, но нет значений | Запись не равна действующей лицензии или праву на getter; посмотреть PERMISSION_DENIED/METHOD_MISSING/MISSING_VALUE отдельно. |
| -1 или нет внешней SD-карты | Нет числового замера; это не нулевой объём и не доказанная деградация. |

Для сети используйте актуальные требования Samsung License Management и корпоративного proxy/firewall; не отключайте TLS verification и не закрепляйте случайные IP. Отдельно проверяйте доступ именно из сети устройства. Фиксированного неподтверждённого списка доменов это руководство не задаёт.

## Сборка и доказательства

Скачайте указанный архив в `.tools/knox/Knox-SDK-3.13-(API-level-40).zip`. `scripts/knox-sdk.sha256` фиксирует SHA-256; `python3 scripts/prepare-knox-sdk.py` проверяет его и извлекает только JAR в `app/build/knox/`. Gradle выполняет это автоматически и подключает compileOnly. SDK stub не упаковывается в APK. Несовпадающий/отсутствующий SDK останавливает сборку с ошибкой; ключ не нужен для сборки или обычного запуска.

На SM-T225 / Android 14 / Knox API 37 проверены импорт dev key и реальная успешная активация (код 0), два внутренних счётчика ёмкости доступны, внешние возвращают отсутствие данных. Внутренние значения были доступны до активации: успех лицензирования не доказывает необходимость лицензии для этих методов. Доставка через SOTI и старые версии Knox пока **не проверены**. [Матрица SDK](knox-api-matrix.md) и [отчёт проверки code39](VALIDATION-knox-code39.md) фиксируют границы результата.

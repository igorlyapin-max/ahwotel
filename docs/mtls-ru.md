# Взаимная TLS-аутентификация OTLP (mTLS)

[English](mtls.md)

AHWOTel поддерживает режимы **None** (по умолчанию) и **mTLS** для OTLP HTTP/protobuf. None допускает HTTPS с проверкой сервера; обычный HTTP включается отдельным разрешением для тестового стенда. В mTLS обязательны HTTPS, доступный приложению ключ Android KeyChain, проверка цепочки сервера и hostname. Ошибка не переключает приложение на None/HTTP и не отключает проверку сертификатов. Локальные измерения продолжаются, недоставленные пакеты остаются в очереди с прежними ограничениями возраста/объёма и повторами отправки.

## Настройка пилота

1. Выпустите индивидуальный клиентский сертификат и ключ. PKCS#12 содержит закрытый ключ и цепочку: установите его средствами Android для **VPN и приложений** либо через MDM. Пароль передайте защищённым способом; его нельзя помещать в deployment JSON. Сам AHWOTel закрытые ключи не импортирует и не экспортирует.
2. Настройки → Выгрузка OTLP → Аутентификация → **mTLS** → **Выбрать клиентский сертификат**. Подтвердите доступ приложения. Наличие сертификата в настройках Android ещё не означает доступ AHWOTel к ключу. Alias можно ввести вручную, если MDM уже предоставила доступ.
3. Укажите `https://<имя или IP сервера>:4318/v1/metrics`. Именно это DNS-имя или IP должно присутствовать в SAN сертификата сервера.
4. Выберите системное доверие для цепочки, доверенной системному хранилищу Android. Для частного УЦ выберите **Импортированный УЦ сервера**, импортируйте публичный PEM/DER-набор сертификатов УЦ размером до 64 KiB. Приложение сохранит ссылку SHA-256. Это доверие действует только в приложении; установка клиентского сертификата или Wi-Fi УЦ его не заменяет. Пользовательский набор УЦ заменяет системный для этого транспорта.
5. Нажмите **Проверить соединение**. Проверяется текущий черновик: показываются владелец, издатель и сроки; проверяется назначение/время клиентской цепочки, выполняется пробная подпись для подтверждения доступа к ключу и отправляется пустой запрос OTLP. Публичные сведения сертификата в логи не пишутся. Успех означает принятие TLS/OTLP-запроса, но не запись измерений в Prometheus. Включите OTLP, сохраните настройки и проверьте числовые точки своего устройства/сессии в Prometheus/Grafana.

Смена endpoint, режима аутентификации, alias или доверия/ссылки УЦ отменяет запросы и очищает очередь выгрузки. Локальная история сохраняется. Продление сертификата под тем же alias очередь не очищает: перед каждым запросом загружается актуальная пара ключ/цепочка и создаётся новое соединение. Уже принятый сервером запрос отозвать нельзя.

## Требования к сертификатам и шаблону выпуска

| Свойство | Клиент | Сервер |
| --- | --- | --- |
| Назначение X.509 | Конечный сертификат, `CA:FALSE` | Конечный сертификат, `CA:FALSE` |
| EKU | Явный `Client Authentication` (`1.3.6.1.5.5.7.3.2`) | `Server Authentication` (`1.3.6.1.5.5.7.3.1`) |
| Key Usage | При наличии KU обязателен `digitalSignature`; лучше указать явно | Подпись, пригодная для TLS |
| Алгоритм | RSA или EC, поддерживаемый KeyChain/TLS на устройстве | Совместимый с TLS клиента |
| Срок | Вся переданная цепочка действительна по часам устройства | Действительная цепочка, SAN соответствует endpoint |
| Доверие | Collector доверяет УЦ клиента; клиент передаёт промежуточные сертификаты | Системное доверие Android либо явно импортированный УЦ |
| Ключ | В том же Android user/work profile, что AHWOTel; приложению выдан доступ | Читается непривилегированным пользователем Collector |

Для нового корпоративного шаблона рекомендуются RSA 2048+ или EC P-256+, SHA-256 или сильнее, индивидуальный ключ каждого устройства, явные `digitalSignature`, `CA:FALSE`, `clientAuth`, цепочка промежуточных УЦ. Ключ должен допускать фоновую подпись без PIN/биометрии при каждой операции; иначе выгрузка будет ждать доступной идентификации, а локальный сбор продолжится. Неизменяемый инвентарный идентификатор в subject/SAN добавляется по правилам вашей PKI; конкретный CN/email приложению не требуется. Предпочтительна генерация неизвлекаемого аппаратного ключа через устройство/MDM; поддержку enrollment надо подтвердить отдельно. Общими могут быть УЦ и шаблон, но не закрытый ключ всего парка.

EAP-TLS для Wi-Fi тоже может использовать `clientAuth`: его **шаблон выпуска** иногда можно адаптировать. Однако **запись Wi-Fi** часто находится в хранилище Wi-Fi, другом профиле или имеет политику, запрещающую приложениям подпись. Корневой сертификат вообще не содержит клиентского закрытого ключа. Повторное использование возможно только при подходящих EKU, сроках, доступе к ключу, доверии сервера и разрешении корпоративной политики. Подходящесть установленного Samsung-сертификата ещё не подтверждена: нужен успешный тест непосредственно из AHWOTel. Для телеметрии предпочтительны отдельные шаблон/ключ с независимыми продлением и отзывом.

## SOTI и массовое развёртывание

### Правила сертификата (schema 4 / code33)

В настройках доступны **Ручной сертификат** и **Правило сертификата**. Все заполненные условия объединяются через AND: OID шаблона AD CS (расширение `1.3.6.1.4.1.311.21.7`), OID политики сертификата (`2.5.29.32`), точный SAN URI назначения, DN издателя и Subject OU. В режиме mTLS по правилу обязателен OID шаблона/политики либо URI назначения; одного издателя или clientAuth недостаточно. Используйте согласованный корпоративный шаблон телеметрии. Создание правила из выбранного сертификата копирует OID шаблона, иначе первый OID политики: проверьте назначение этого значения перед распространением. Индивидуальные Subject CN/SAN, serial и fingerprint автоматически не копируются.

Объект `auth` schema 4 дополнительно содержит обязательные `selection` (`manual` по умолчанию или `rule`), `delegated` (по умолчанию false) и `rule` со строками `templateOid`, `policyOid`, `sanUri`, `issuer`, `ou`. В режиме правила alias общего экспорта всегда пустой. Старые локальные настройки переводятся в ручной режим; deployment JSON schema 1–3 нужно экспортировать заново.

SOTI передаёт отдельные Android managed restrictions вместе с профилем или последующим обновлением:

```text
tls_client_alias = <индивидуальный alias сертификата>
tls_client_profile_id = <действующий profileId>
tls_client_profile_revision = <действующая целочисленная revision>
```

Все три поля передаются вместе. Отсутствующая или устаревшая привязка блокирует отправку. Макрос SOTI `%CertificateTemplate_<Macro-Template-Name>%` — кандидат для подстановки alias; его фактический результат надо проверить на SOTI 2026.2.2.1001. Неразрешённые макросы отклоняются. Обновление привязки не меняет revision общего профиля: при продлении можно сменить индивидуальный alias без очистки очереди. Смена правила/доверия/endpoint очищает очередь, сохраняя историю. Приложение использует предоставленный alias, а не перебирает системное хранилище.

Для автоматического доступа предпочтительна выдача grant самим Device Owner. Альтернатива: включить **Разрешить делегированный доступ** в общем профиле и назначить AHWOTel роль **Certificate Selection** через SOTI. Самостоятельная выдача доступа требует Android 11+, активного полного управляемого профиля, подходящей привязки, разрешающего флага и фактической `delegation-cert-selection`. Доступ выдаётся только собственному пакету; сертификат читается и проверяется до подписи. Новый grant отзывается при неуспешной проверке. Receiver не выбирает сертификаты и не выдаёт доступ другим приложениям. Android допускает одного делегированного обработчика; отсутствие автовыбора для других приложений может изменить их прежний автоматический сценарий VPN/SSO. Перед распространением обязателен пилот SOTI/VPN/SSO; конкретная настройка консоли для выбранного способа доставки APK пока не подтверждена.

Проверки прав, назначения, сроков и правила выполняются при запуске, изменении настроек/KeyChain и перед отправкой. Изменения KeyChain отменяют запросы; проверка соединения показывает локализованные причины. В управляемом режиме правила фоновые диалоги выбора и понижение защиты не используются. Без делегирования уже предоставленный ключ доступен по-прежнему. Для прекращения доступа отзовите grant ключа и отключите автовыдачу в политике либо снимите делегирование: иначе следующая разрешённая проверка может восстановить grant. Локальные измерения и ограниченные повторы продолжаются.

Ключ и сертификат выпускаются каждому устройству отдельно. Затем MDM предоставляет пакету `com.ahwotel` доступ к KeyChain alias в том же профиле. Device/profile owner может использовать соответствующие API DevicePolicyManager; доступность зависит от версии Android, роли администратора и возможностей SOTI. Строка alias в конфиге сама по себе разрешения не выдаёт. Конкретный сценарий установки и выдачи доступа SOTI нужно проверить в среде заказчика; установка Wi-Fi payload не доказывает доступ приложения к его ключу.

Экспорт/импорт использует schema **4**. Объект `auth` располагается отдельно от `settings`:

```json
{"mode":"mtls","alias":"ahwotel-client","trust":"custom","trustRef":"<64 строчных шестнадцатеричных символа SHA-256>","selection":"manual","delegated":false,"rule":{"templateOid":"","policyOid":"","sanUri":"","issuer":"","ou":""}}
```

`mode`: `none` (по умолчанию) или `mtls`. `trust`: `system` (по умолчанию) или `custom`. В новом None-профиле alias/reference пустые. Для парка используйте общий логический alias, который на каждом устройстве указывает на его собственный ключ. Общий JSON не содержит ключ, байты сертификата, пароль PKCS#12 или `deviceId` установки.

Публичное доверие серверу доставляется независимо строковым Android managed restriction **tls_ca_bundle**: вместе с `management_action=apply`/`deployment_profile` либо отдельным обновлением только УЦ:

```json
{"ref":"<SHA-256 точных UTF-8 байтов PEM>","pem":"-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----\n"}
```

Размер `pem` после UTF-8-кодирования — до 64 KiB; всего JSON — до 140000 байтов. Разрешены только публичные сертификаты УЦ. Хеш считается по точным байтам: окончания строк и завершающий перевод строки влияют на результат. Набор сохраняется по хешу в приватном каталоге и переживает обычное `adb install -r`. Неверный хеш, сертификат не-УЦ или превышение размера отклоняются. Отсутствующий набор блокирует отправку без расширения доверия. В управляемом полном профиле настройки, включая аутентификацию и импорт УЦ, доступны только для чтения; язык, просмотр результатов и проверка соединения остаются доступны. Профили schema 1/2/3 нужно заново выпустить как schema 4 с повышением revision; их применение не поддерживается, но сохранённую доверенную оболочку управления можно явно освободить через release.

## Политика администратора: транспорт и Android

Локальная проверка соединения в режиме правила проверяет выбранный эталонный ключ без выдачи MDM grants. Управляемая отправка требует отдельную принятую привязку устройства. Асинхронное создание правила сохраняет свежие изменения и отбрасывает устаревший результат. Смена binding и generation sender защищены общей блокировкой; смена только binding сохраняет очередь телеметрии.

Для актуальной Android → Prometheus приёмки запустите instrumentation с `--mtls-lab-endpoint https://127.0.0.1:14318/v1/metrics`, затем `python3 scripts/check-mtls-android.py emulator-5554 --run artifacts/review-fixes36/android.run.json` (укажите manifest рядом со своим отчётом). Runner создаёт run ID; checker требует успешную instrumentation и сверяет все исходные Room-точки данного запуска/сессии. Старые файлы результатов не поддерживаются. Нужен отдельный Collector с сертификатами текущего тестового APK и ADB reverse; после проверки остановите его и удалите reverse.

Защиту транспорта выбирает администратор. `allowHttp` выключен по умолчанию; его явное включение разрешает передачу телеметрии без шифрования и является принятым риском развёртывания (ASPM 114496), а не false positive. None означает отсутствие клиентской сертификатной аутентификации: HTTPS с обычной проверкой сервера остаётся доступен. mTLS всегда требует HTTPS и не переключается на HTTP при ошибке.

Поддержка Android 8+ сохраняется. Пустой task affinity основной Activity и запрет task reparenting — дополнительное усиление, не полное исправление StrandHogg 2.0 (ASPM 114497). `targetSdk=36` не исправляет старую ОС. Администратор должен проверять обновления безопасности производителя через MDM; для старых непропатченных устройств остаётся риск платформы. Согласно [рекомендации Android](https://developer.android.com/privacy-and-security/risks/strandhogg), Android 11+ содержит необходимые исправления. Стандартный launch mode сохранён для системных окон файлов и KeyChain.

## Проверка на локальном стенде

Генератор сертификатов — локальный инструмент администратора/сборки, не сетевой обработчик загрузок (ASPM 120211). Выбор каталога вывода предусмотрен намеренно. Отклоняются `..`, symlink/junction в существующих компонентах пути, файлы вместо каталогов и непустой каталог вывода. На POSIX каталог вывода должен принадлежать текущему пользователю без прав группы/остальных; новые каталоги создаются с `0700`. Родительский каталог должен быть доверенным: проверка не является песочницей от процесса, который может одновременно подменять родительские каталоги. Генератор не исправляет права существующего каталога автоматически и не перезаписывает ключи. Smoke использует приватные временные каталоги, Gradle — игнорируемые generated test assets.

Нужны [существующий стенд](../deploy/otel-lab/README.md), OpenSSL, правильные часы и явный `LAB_BIND_ADDRESS`. Из корня проекта:

```bash
./scripts/otel-lab.sh up                         # None для нового .env по умолчанию
./scripts/otel-lab.sh certs                      # существующие ключи не перезаписывает
stat -c %g deploy/otel-lab/.runtime/mtls/server.key
```

В `deploy/otel-lab/.env` задайте `OTLP_AUTH_MODE=mtls` и `MTLS_CERT_GID=<числовая группа из stat>`, затем:

```bash
./scripts/otel-lab.sh up --collector-only
```

При первом запуске используйте `up` без `--collector-only`, чтобы поднять все компоненты. Переключение с этим флагом пересоздаёт только Collector, сохраняя volumes и работающие Prometheus/Grafana. Тот же порт 4318 принимает HTTPS с обязательным клиентским сертификатом; параллельного HTTP-входа нет. Анонимный Viewer Grafana и локальные health/admin-порты — отдельный контур: mTLS защищает приём телеметрии, не интерфейс Grafana.

Тестовые материалы создаются в игнорируемом Git каталоге `.runtime/mtls/`: `ca.crt`, `server.crt`, `server.key`, `client.crt`, `client.key`, `client.p12`, `client-password.txt`, ключ тестового УЦ. SAN сервера содержит заданный IP, `localhost`, `127.0.0.1`. Срок УЦ — 30 дней, конечных сертификатов — 14 дней. В Collector монтируются только серверный ключ/сертификат и публичный УЦ клиентов; ключ УЦ не монтируется. Защитите каталог. Передайте тестовый P12 и пароль на тестовое устройство контролируемым способом, установите для VPN/приложений, импортируйте `ca.crt` в AHWOTel и выберите alias. Эти ключи предназначены для стенда, не для корпоративного парка. Смена IP требует перевыпуска сервера с правильным SAN; отказ `certs` от перезаписи сделан намеренно.

При продлении сервера замените его цепочку/ключ и перезагрузите Collector. Клиентский сертификат обновляйте под тем же alias с сохранением доступа приложения. При смене УЦ предварительно доставьте набор со старым и новым УЦ, обновите reference/revision профиля: такая смена доверия очищает очередь. Ключ УЦ храните отдельно, никогда не отправляйте на устройства. Для возврата лёгкого стенда задайте `OTLP_AUTH_MODE=none`, обновите Collector и явно выберите None/HTTP в приложении.

```bash
python3 scripts/test_mtls_lab.py
./scripts/gradle.sh :app:testDebugUnitTest --tests com.ahwotel.MtlsTest --tests com.ahwotel.LabWireFixtureTest --rerun-tasks
./scripts/otel-lab.sh smoke
python3 scripts/mtls_lab_smoke.py
```

`smoke` отправляет protobuf, сформированный сериализаторами APK, и проверяет числовые значения/время в Prometheus. `mtls_lab_smoke.py` дополнительно требует mTLS, проверяет отказ без сертификата, с неподходящим клиентом, неверным УЦ/hostname и по HTTP; сохраняет обезличенные результаты. Кнопка в приложении не заменяет эту сквозную проверку.

Изолированный `MtlsAcceptanceTest` дополнительно проверяет Android TLS, смену настроек очереди и EN/RU. Тест установки ключа работает только на эмуляторе: временные сертификаты генерируются Python/OpenSSL при `assembleAcceptanceAndroidTest` и включаются только в тестовый APK. Через системные диалоги устанавливается запись VPN/apps и выдаётся настоящий доступ KeyChain. Параметр `scripts/instrument.sh --mtls-lab-endpoint https://127.0.0.1:14318/v1/metrics` добавляет реальный шестисекундный сбор RAM; нужен отдельный тестовый Collector с точно теми серверным сертификатом/УЦ клиента, которые сгенерированы для тестового APK, и ADB reverse. Его нельзя направлять на постороннюю или промышленную PKI. Подтверждения и границы: [проверка code32](VALIDATION-mtls-code32.md).

## Ошибки, диагностика и ограничения

Ключ отсутствует/доступ запрещён: повторите выбор или исправьте MDM grant. Сроки: проверьте часы и enrollment. Назначение: перевыпустите с clientAuth/signing. Нет УЦ: доставьте публичный набор по reference. Hostname: исправьте SAN/endpoint. TLS handshake: проверьте цепочки, доверие с обеих сторон и политику Collector. HTTP-код/некорректный OTLP-ответ: TLS мог пройти, но OTLP-запрос не принят. Загрузчик пишет ограниченный набор диагностических кодов через существующие stdout/stderr, Logcat и JSONL; по умолчанию Off, доступны Basic и временный Verbose. Закрытые ключи, PEM и пароли в логи не выводятся.

mTLS доказывает владение сертификатом, который допускает listener. Эта версия не авторизует отдельные subject и не связывает OTLP `device.id` с сертификатом. Доверенный клиент может заявить атрибуты payload; проверка корпоративного инвентаря и индивидуальная авторизация потребуют политики ingress/PKI. Автоматические CRL/OCSP и enrollment не реализованы. Отзывайте ключ/доступ или меняйте политику listener по требованиям эксплуатации: удаление устройства из SOTI само по себе не доказывает немедленный отказ сервера его ранее выпущенному сертификату.

Источники: [Android KeyChain](https://developer.android.com/reference/android/security/KeyChain), [DevicePolicyManager](https://developer.android.com/reference/android/app/admin/DevicePolicyManager), [Collector TLS configuration](https://github.com/open-telemetry/opentelemetry-collector/blob/main/config/configtls/README.md).
